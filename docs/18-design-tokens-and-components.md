# 18 · Design tokens and components (as built)

> Version: 1.0 · Last updated: 2026-10-25 · Written from the code in `packages/design-tokens`, `apps/admin-console/src/components` and `apps/member-app/src/ui`.
> Design intent and visual rules live in `docs/12-design-system.md`. This doc describes what was actually built and how to use it.
> The living version is the console's **Design System** page (`/design`, Super Admin only).

## 1. One look, two apps

Both apps wear **Juspay Blend** (D-047), Blend version `0.0.38`, in its own brand blue.
- **Admin Console:** uses `@juspay/blend-design-system` directly. The tokens are fed to Blend through `createBlendFoundation()`, and also exported as CSS variables and Tailwind classes.
- **Member App:** Blend has no React Native package, so `apps/member-app/src/ui` is a small native kit. It copies Blend's prop names (`buttonType`, `size`, `subType`, Tag `color`/`type`) and reads the same tokens. If `@juspay/blend-native` is ever published, the kit can be swapped mechanically.

The design system is **frozen** for the demo. Bugs get fixed; nothing is restyled.

## 2. Token tiers (`packages/design-tokens/src`)

| Tier | File | What it holds |
|---|---|---|
| 1 Foundation | `foundation.ts` | A mirror of Blend's FOUNDATION: palette scales, font sizes, shadows, breakpoints |
| Brand | `brand.ts` | The only place the society differs from stock Blend: app names, legal name, Regd. No. P-929, `primaryScale`, font families. Rebrand = swap `primaryScale` (Q-008), then run `npm run tokens` |
| 2 Semantic | `semantic.ts` | `light` and `dark`, with the same role names: `bg`, `text`, `border`, `brand`, `status.{success,warning,danger,info,neutral,approval}`, `money.{credit,debit,neutral}`, `chart` |
| 2 Semantic | `typography.ts` | `textRoles` (console) and `nativeTextRoles` (app, one step larger) |
| 2 Semantic | `layout.ts` | `space` (4-pt rhythm), `spacing` (inset/stack/inline/gutter), `radius` (control 10, card 12, sheet/modal 16), `borderWidth`, `elevation`, `motion`, `layers`, `layout` |
| 3 Platform | `blend.ts` | `createBlendFoundation()`: tokens → Blend theme (console) |
| 3 Platform | `native.ts` | `nativeTheme`, `nativeElevation`, `nativeText` (app) |
| 3 Platform | `css/tokens.css` | CSS variables generated by `npm run tokens`. Tailwind classes such as `bg-surface`, `text-fg-secondary` and `rounded-card` point at them |
| Status | `status.ts` | `Tone`, `toneToBlendColor`, `presentStatus()` (§6) |

One change after the freeze: `text.tertiary` is `#666C79` instead of gray-500, so captions pass WCAG AA on every surface (D-064).

**Z-order (`layers`):** base 0 · sticky 10 · header 99 · dropdown 1000 · drawer 1100 · modal 1200 · toast 9999.
This is why a Blend dropdown opened inside a drawer renders underneath it. Use `Chips` there instead (docs/19 §2).

## 3. Colour roles

Screens use the role, never the scale step. For example, write `text.secondary` and not gray-600.
- **Status colours** each have four parts: `fg` (text on a tint), `bg` (tint), `border` and `solid` (dots and progress bars).
- **Money colours:** credit is green-700, debit is red-700.
- **Chart order:** brand-500, then purple, orange, green, yellow, gray, red. Muted series, with one highlight.

## 4. Typography

Inter Variable is self-hosted. The optical-size axis gives the Display cut at large sizes. Console base text is 14/20; the app's base is 16/24.

| Role | Use |
|---|---|
| `display` | Login hero, celebration numbers |
| `pageTitle` | One per page: the PageHeader title |
| `sectionTitle` | Section headers, drawer titles |
| `cardTitle` | Card, Panel and list-group titles |
| `metric` / `metricSm` | KPI values (tabular) |
| `bodyLg`, `body`, `bodyStrong`, `label` | Running text and form labels |
| `caption`, `captionStrong`, `overline` | Hints, meta lines, small uppercase labels |
| `amount` / `amountLg` | Money in tables and summaries (tabular) |
| `mono` | IDs, UTR numbers (tabular) |

In the console, every role is also a Tailwind class (`text-page-title`, `text-caption`, …). In the app, use `<Text role="…" tone="…">` from `ui/Text.tsx`.

## 5. Tabular numerals

Money, counts and IDs line up in columns:
- **Console:** the `.tabular` class (`font-variant-numeric: tabular-nums`, `apps/admin-console/src/index.css`), plus every role marked `tabular: true`.
- **App:** `nativeText` sets `fontVariant: ['tabular-nums']` on the same roles.

All money is formatted by `formatINR()` from `@tgs/domain`, with Indian grouping (`₹1,00,000.00`).

## 6. Status presentation

There is one map for every workflow status: `presentStatus(entity, status, audience)` in `status.ts`.
- **Entities:** `loan`, `membership`, `deposit`, `demandSheet`, `surety`, `schedule`, `paymentReport`, `changeRequest`, `member`, `ticket`.
- It returns a **tone** (neutral / info / warning / success / danger / approval) and a **label**.
- Staff and members can see different words for the same status. For example, staff see "DDO certification" where a member sees "Department verification".
- An unknown status falls back to neutral with the raw status in lower case.

Never colour or label a status by hand:
- **Console:** `components/StatusTag.tsx` (Blend `TagV2`, subtle, rounded, `toneToBlendColor[tone]`).
- **App:** `ui/Tag.tsx` → `StatusTag` (audience defaults to `member`).

The Design System page → Status tab lists every key (`STATUS_PRESENTATION_KEYS`).

## 7. Components

### Console (`apps/admin-console/src/components`)

Blend V2 components are used as they are: `ButtonV2`, `TagV2`, `AlertV2`, `TableV2`, `TabsV2`, inputs, `Skeleton`, `Spinner`, `EmptyState`, `DrawerV2` and the sidebar shell. Thin wrappers add only what Blend lacks:

| Component | Job |
|---|---|
| `PageHeader`, `SectionTitle` | Page title (one `h1`), description, status meta, actions |
| `Panel` | Card with a title row. Used on the dashboard and detail pages |
| `SideDrawer` | The decision drawer: right-hand sheet on Blend's headless `DrawerV2`, at layer 1100 |
| `Chips` | Radio chips (`role="radiogroup"`). Used instead of dropdowns inside drawers |
| `StatusTag` | §6 |
| `RuleCheckList` | Shows each eligibility or business-rule outcome with its `BR-` id, never a bare "invalid" |
| `ViewState` | The ten-state contract (docs/19 §3) |

### Member App (`apps/member-app/src/ui`)

| File | Components |
|---|---|
| `Text.tsx` | `Text` (role + tone) |
| `Button.tsx` | `Button` (primary / secondary / danger, sizes, loading) |
| `Tag.tsx` | `Tag`, `StatusTag` |
| `Surfaces.tsx` | `Card`, `Alert`, `Section`, `KeyValue`, `Divider` |
| `Fields.tsx` | `TextField`, `DateField`, `SelectField` (opens a bottom sheet; its trigger is named "Field: value"), `OtpInput` |
| `Choice.tsx` | `ChoiceCard`, `YesNo`, `Checkbox`, `Segmented`, `NumberStepper` |
| `Progress.tsx` | `WizardProgress`, `StageTracker` (the joining and loan trackers) |
| `Layout.tsx` | `Screen` (scroll, pull-to-refresh, sticky footer), `Header`, `Hero`, `EmptyState`, `Skeleton` |

Icons: Lucide only (`lucide-react`, `lucide-react-native`).

## 8. Accessibility (checked by tests)

`tests/e2e/a11y-console.spec.ts` and `a11y-phone.spec.ts` run axe against WCAG 2.2 AA:
- every console route, in light and dark;
- every phone screen.

Critical or serious findings fail the build. Fixes made because of this:
- the tertiary text colour (D-064);
- a duplicate `<main>` landmark in the console shell (fixed 2026-10-25);
- see `docs/build-history/11-demo-ready.md`.

## 9. The rule for feature code

Screens use **Tier 2 roles only**: semantic colours, text roles and spacing roles. Raw hex values or pixel sizes in a screen are a review failure.

There is **no automated lint rule** for this yet. It is enforced by review. One deliberate exception: the printable FDR twin (`pages/deposits/FdrPage.tsx`) uses fixed ink colours, because it imitates the paper receipt in both themes.
